# Case Builder

Run `node DesignDevelopment/CaseBuilder/server.cjs` from the repository root, then open http://127.0.0.1:8766/. No install step. This server is separate from the pitch reviewer on 8765.

Each definition is a readable `cases/<id>.json` file. Dev fields save valid edits after a 300 ms pause. Advanced opportunity JSON exposes prerequisites, checks, item/resource costs, outcomes and notes. The full JSON editor can also change the roster, rules, endings and starting state. Use **Rebuild structured controls** after a full-JSON edit. Add/remove opportunities and endings using the buttons; remove references before deleting. Newly created files appear as untracked Git files until staged. The supplied sample and implementation are tracked in Git.

Edits are immediately backed up in this browser's localStorage, including invalid JSON. Only matching server acknowledgments clear a draft. Reload restores pending drafts; a revision mismatch requires an explicit choice before replacing disk. Download draft exports both parsed definition and any invalid JSON buffers. Browser storage can be unavailable or cleared, so the header reports backup/save errors and unsaved changes trigger an unload warning. Existing review-app storage is untouched. Case saves use serialized atomic writes and optimistic revision checks; there is no cloud persistence.

Test (formerly Preview) is a separate, disposable runtime. Drag an investigator from the bottom tray into an opportunity slot, or select its card and click the slot. Portraits move out of the tray into matching-size slots. Drag a portrait to another slot or back to the tray; selecting a slotted portrait then clicking the tray also returns it. Replacing an occupied slot returns the previous investigator to the tray. Opportunity borders turn green only when all slots and prerequisites are satisfied. Each investigator can occupy at most one opportunity per turn. Click **Complete turn** after the opportunities in the current turn column to resolve fully prepared actions. Item-only actions do not use investigators. Actions resolve in preparation order; costs and prerequisites are checked again as they resolve. Newly unlocked opportunities can be assigned next turn. A turn advances by the longest assigned action duration (or one turn for waiting). This is an explicit prototype scheduling assumption, not a finalized design. It does not model multi-turn occupied investigators. A deadline of 8 expires when the next turn becomes 9; active deadline actions apply their `expired` effect and leave the board.

Provisional check: `1d(sides) + sum(check.skills) * rule.multiplier + held-item bonuses >= target`. Die size, skill multiplier, targets and bonuses are editable. Item bonuses apply after costs. Missing skills count as zero. This formula is a placeholder: the base doc defines skill checks, not their mathematics. The eight documented stats are Exploitability, Focus, Interpersonal, Violence, Sly, Knowledge, Resilience and Otherness. Health is also provisional. Zero health prevents assignment. Resources and items cannot drop below zero. Successful or failed nonrepeatable opportunities leave the board; set repeatable for retries and explicitly remove them on success. Unlock cannot reactivate a completed nonrepeatable opportunity.

Outcome fields: `inventory` and `resources` are numeric deltas; `skills` and `health` affect the assigned investigator; `flagsAdd/flagsRemove` change clues; `unlock/remove` refer to opportunity IDs; `ending` refers to an ending ID or null. `requires` supports flags, forbidden flags, minimum items/resources/skills and investigator traits. `cost` consumes items/resources on either result. Outcome/check/opportunity/case notes are editor annotations.

Sample: **The Opening Act**, accepted pitch C01-P01, revised to follow the saved review notes. Research or interview reveals the musical connection; pay for an amplifier or borrow it with a check; observe the visitors; deliberately disappoint them or perform competently and acquire an unwanted residency. No lethal notes. Source provenance and exact saved review notes are embedded in the case file. All opening, action, outcome and ending prose is editable.

The collapsed **Current test overrides** section in Test Setup edits only runtime skills, traits, health, inventory and resources. They never save the definition. Restart clears the run; setup or definition edits show a pending-change notice; Restart test explicitly applies them. The current run keeps its original definition and progress until then. Runtime progress is not saved. This is a single-case mechanics sandbox, with placeholder cards, no art pipeline, campaign progression, graph canvas or long-running event scheduler.

Focused checks: `node --test DesignDevelopment/CaseBuilder/smoke.test.mjs` uses disposable fixture files and deterministic rolls; it checks file persistence/conflicts, dynamic case IDs, checks, branches, items, requirements, health, deadlines and runtime isolation. It never writes the supplied case or pitch reviews.

Test Setup displays all 24 restored portraits with documented stats. Toggle cards to save `testSetup.investigatorIds` in that case JSON using the same autosave, browser draft and conflict protections. Only selected investigators appear in the Test tray and new-run roster. Without explicit setup, defaults are the portrait-backed members of the case roster (Avery and Dr. Vanderhorten in the sample; Red has no restored portrait). Existing case member stats are retained; other members use document baselines. Gabriel, Scooter and Xavier have no documented stats and remain disabled at the end of the list. Test-only overrides still never save to the definition.

Test Setup shows all eight skills in canonical order. Click a star to set a per-case effective value from 1–6. Clicking the first star when the value is already 1 clears it to 0. Returning a skill to its base value removes that override. Purple stars indicate a value differing from baseline; empty stars are dimmer in either color. Values live in testSetup.skillOverrides, never in the portrait catalog; existing Test runs apply changes only after Restart test. Investigators explicitly lacking documented baseline stats remain disabled at the end of the list.

Test uses a single opportunity board above a two-row card dock: investigators first, then inventory/resource cards. Slots derive from existing `requires.inventory/resources` and `cost.inventory/resources`, using the larger quantity for each name. Optional check item bonuses do not create required slots. Item-only actions have no investigator slot; resource-only actions use the actual resource cards (for example money), while actions requiring no cards expose a Prepare action control. No starting items are invented. Required quantities are reserved while slotted; costs are consumed only once by the existing engine on resolution, and nonconsumed requirements remain in inventory. Wrong card types/names and overbooked quantities are rejected. Partially prepared or blocked actions do not resolve; completing an empty turn still advances time and deadlines. Each completed turn keeps its cards on the board without interactive slots: unused cards are grey, successful cards green, and failed cards red. Outcome text appears on chosen cards; the next turn appears in a column to the right. The opening description remains visible. Temporary run changes never save case definitions.

Test Setup ratings range from 0 to 6. Hovering an investigator slot shows each relevant effective skill as +X. Checks display the skill name followed by outlined stars up to the difficulty. With an investigator assigned, guaranteed totals are solid and possible totals are half-filled; possible totals beyond the difficulty have no outline. Resolved checks show solid stars up to the actual rolled total. Check modifiers use the same skill and post-cost item-bonus calculation as resolution. Skill checks sit directly above slots at the bottom of each card.

Test displays a horizontally scrollable timeline with one column per resolved turn and a rightmost column of all currently available opportunities. Compact buttons expand into panels. Only current panels contain assignment controls; historical panels retain grey, inert copies of their assigned investigators and item quantities, actual rolled stars, outcome text, and per-action inventory/resource changes (including costs). Connections run from the first actual unlocking card to the newly revealed opportunity; when several cards unlock it in one turn, the topmost card wins regardless of preparation order. Only reached endings appear. Restart clears disposable runtime history; Dev and authored case files remain unchanged.

The Test stage fills the space between the main toolbar and inventory tray. Drag the stage to pan horizontally or vertically; scrollbars are hidden. Past-turn shading fills the stage to the left of a divider halfway between the past and current columns. Matching opportunities in consecutive turns connect with grey dotted lines. The opening is an expanded-by-default card in the first column; Restart test appears only in the Test toolbar. Completed cards hide unused slots and unattempted checks while retaining assigned card ghosts. Complete turn is the last item in the current column. Duration labels are omitted while scheduling remains provisional.
