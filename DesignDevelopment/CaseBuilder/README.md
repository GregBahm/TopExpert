# Case Builder

Run `node DesignDevelopment/CaseBuilder/server.cjs` from the repository root, then open http://127.0.0.1:8766/. No install step. This server is separate from the pitch reviewer on 8765.

Each definition is a readable `cases/<id>.json` file. Dev fields save valid edits after a 300 ms pause. Advanced opportunity JSON exposes prerequisites, checks, item/resource costs, outcomes and notes. The full JSON editor can also change the roster, rules, endings and starting state. Use **Rebuild structured controls** after a full-JSON edit. Add/remove opportunities and endings using the buttons; remove references before deleting. Newly created files appear as untracked Git files until staged. The supplied sample and implementation are tracked in Git.

Edits are immediately backed up in this browser's localStorage, including invalid JSON. Only matching server acknowledgments clear a draft. Reload restores pending drafts; a revision mismatch requires an explicit choice before replacing disk. Download draft exports both parsed definition and any invalid JSON buffers. Browser storage can be unavailable or cleared, so the header reports backup/save errors and unsaved changes trigger an unload warning. Existing review-app storage is untouched. Case saves use serialized atomic writes and optimistic revision checks; there is no cloud persistence.

Test (formerly Preview) is a separate, disposable runtime. Assign each investigator to at most one opportunity, then resolve the turn. Item-only actions do not use investigators. Actions resolve in the visible assignment order; costs and prerequisites are checked again as they resolve. Newly unlocked opportunities can be assigned next turn. A turn advances by the longest assigned action duration (or one turn for waiting). This is an explicit prototype scheduling assumption, not a finalized design. It does not model multi-turn occupied investigators. A deadline of 8 expires when the next turn becomes 9; active deadline actions apply their `expired` effect and leave the board.

Provisional check: `1d(sides) + sum(check.skills) * rule.multiplier + held-item bonuses >= target`. Die size, skill multiplier, targets and bonuses are editable. Item bonuses apply after costs. Missing skills count as zero. This formula is a placeholder: the base doc defines skill checks, not their mathematics. The eight documented stats are Exploitability, Focus, Interpersonal, Violence, Sly, Knowledge, Resilience and Otherness. Health is also provisional. Zero health prevents assignment. Resources and items cannot drop below zero. Successful or failed nonrepeatable opportunities leave the board; set repeatable for retries and explicitly remove them on success. Unlock cannot reactivate a completed nonrepeatable opportunity.

Outcome fields: `inventory` and `resources` are numeric deltas; `skills` and `health` affect the assigned investigator; `flagsAdd/flagsRemove` change clues; `unlock/remove` refer to opportunity IDs; `ending` refers to an ending ID or null. `requires` supports flags, forbidden flags, minimum items/resources/skills and investigator traits. `cost` consumes items/resources on either result. Outcome/check/opportunity/case notes are editor annotations.

Sample: **The Opening Act**, accepted pitch C01-P01, revised to follow the saved review notes. Research or interview reveals the musical connection; pay for an amplifier or borrow it with a check; observe the visitors; deliberately disappoint them or perform competently and acquire an unwanted residency. No lethal notes. Source provenance and exact saved review notes are embedded in the case file. All opening, action, outcome and ending prose is editable.

Test overrides edit only runtime skills, traits, health, inventory and resources. They never save the definition. Restart clears the run; setup or definition edits show a pending-change notice; Restart test explicitly applies them. The current run keeps its original definition and progress until then. Runtime progress is not saved. This is a single-case mechanics sandbox, with placeholder cards, no art pipeline, campaign progression, graph canvas or long-running event scheduler.

Focused checks: `node --test DesignDevelopment/CaseBuilder/smoke.test.mjs` uses disposable fixture files and deterministic rolls; it checks file persistence/conflicts, dynamic case IDs, checks, branches, items, requirements, health, deadlines and runtime isolation. It never writes the supplied case or pitch reviews.

Test Setup displays all 24 restored portraits with documented stats. Toggle cards to save `testSetup.investigatorIds` in that case JSON using the same autosave, browser draft and conflict protections. Only selected investigators appear in the Test tray and new-run roster. Without explicit setup, defaults are the portrait-backed members of the case roster (Avery and Dr. Vanderhorten in the sample; Red has no restored portrait). Existing case member stats are retained; other members use document baselines. Gabriel, Scooter and Xavier have no documented stats and remain disabled at the end of the list. Test-only overrides still never save to the definition.

Test Setup shows all eight skills in canonical order. Click a star to set a per-case effective value from 1–5. Clicking the first star when the value is already 1 clears it to 0. Returning a skill to its base value removes that override. Purple stars indicate a value differing from baseline; empty stars are dimmer in either color. Values live in testSetup.skillOverrides, never in the portrait catalog; existing Test runs apply changes only after Restart test. Investigators explicitly lacking documented baseline stats remain disabled at the end of the list.
